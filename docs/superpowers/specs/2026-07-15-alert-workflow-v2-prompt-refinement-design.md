# 告警简单根因分析 V2 提示词优化设计

## 目标

在不修改工作流拓扑、异常算法、分类规则和证据链的前提下，修正 V2 工作流中不合理的报告表述和排障建议：

1. 保留 Epoll 独立分析方向，但不再默认建议用户使用 `strace epoll_wait` 或 `perf trace epoll:*`。
2. 报告和建议不再把 Pod 作为唯一运行对象，同时适配 VM、容器和未知环境。
3. 禁止 `服务xx`、`xxx实例` 等示例占位符进入最终报告。

## 修改范围

只调整以下 LLM 节点的提示词：

- `1741512806512`：可行动方向建议
- `17430596469370`：llm analysis root cause
- `17473569800940`：网络方向分析
- `1750662084996`：描述
- `1750662408086`：可行动建议JSON
- `1764048001002`：生成报告展示结构
- `1754382620041`：总结下游影响

不修改：

- RTT 检测与归因代码
- RED/P90/Span 查询与合并
- Trace 查询与合并
- 问题分类器
- 节点连接和并行结构

## Epoll 建议

Epoll 仍然可以作为主要异常方向，根因分析规则保持不变。

删除以下默认建议：

- `strace -e epoll_wait,epoll_pwait ...`
- `perf trace -e epoll:* ...`

替换为网络和连接状态排查：

- `ss -s`：查看 socket 汇总状态。
- `ss -antp`：查看 TCP 连接、状态和关联进程。
- `nstat -az`：查看 TCP 重传、连接失败等内核网络计数。
- `sar -n TCP,ETCP 1`：观察 TCP 活跃连接和重传趋势；系统没有 `sar` 时跳过。
- `ip -s link`：查看网卡丢包和错误计数。
- 结合 RTT、下游 Span、连接数、超时和重传判断自身网络或下游依赖问题。

提示词必须明确：只有证据支持时才给命令，不得机械输出全部命令。

## 服务和实例表述

报告使用真实服务变量：

```text
{{#1754299310647.service#}}
```

运行对象使用环境上下文：

```text
{{#v2_runtime_environment_context.instance_term#}}
{{#v2_runtime_environment_context.location_text#}}
{{#v2_runtime_environment_context.prompt_context#}}
```

规则：

- 服务名有值时输出真实服务名。
- 服务名为空时省略服务字段，不输出“服务xx”“未知服务”“空服务”。
- VM 场景使用主机、进程和 PID。
- 容器场景可以使用 Pod 和容器。
- 环境不明确时使用“实例”“运行节点”“进程或服务”等中性术语。
- 不得因为原始指标或工具名称包含“按 Pod 统计”，就推断当前一定是容器环境。

## 占位符治理

最终输出规范中禁止使用：

- `服务xx`
- `xx服务`
- `xxx实例`
- `xxx下游依赖问题`
- `XXXX命令`

示例中的占位符改成清晰的规则或真实示例，例如：

- “具体下游依赖问题，例如 MySQL 下游依赖问题”。
- “使用与当前根因和运行环境匹配的命令”。
- “根据实际服务名和实例标识输出；字段为空时省略”。

知识库引用可以使用“根据知识库文档”，但不得输出“根据xx文档”。

## 报告展示约束

`生成报告展示结构` 的证据映射按环境解释：

- VM：主机 CPU、进程 CPU、load、磁盘 IO、进程状态、系统日志。
- 容器：容器 CPU、CPU throttling、Pod 状态、K8s Event。
- 未知：使用通用 CPU、内存、磁盘、网络和进程证据，不猜测容器状态。

`faultLocation` 和摘要卡片必须使用真实服务、实例、主机或进程标识，禁止占位词。

## 测试

新增提示词静态测试：

1. 最终报告相关提示词不包含 `服务xx`。
2. Epoll 建议不包含 `strace -e epoll_wait`、`epoll_pwait` 或 `perf trace -e epoll:`。
3. Epoll 建议包含网络连接、重传、丢包和 RTT/Span 的处理规则。
4. 关键输出节点引用运行环境上下文。
5. 根因分析使用真实服务变量和环境位置变量。
6. VM、容器和 unknown 环境上下文的既有测试继续通过。
7. 工作流图、代码节点 Schema、RTT、Span、Trace 相关回归测试继续通过。

## 验收标准

- Epoll 方向保留，建议改为基于网络证据的排查方式。
- 报告不再输出 `服务xx`。
- VM 报告不再以 Pod 作为实例名称。
- 容器环境仍可使用 Pod/容器术语。
- 没有修改工作流节点连接和分析算法。
- 所有新增和既有专项测试通过。
